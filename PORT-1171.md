# Port notes and references

Baseline: Legacy Console 1.11.2 version 1.9.6. The old project and releases remain separate.
Target: Minecraft 1.17.1, Forge 37.0.103, OptiFine H1 when shaders are enabled.

LCE reference: https://github.com/chrisGrando/MinecraftLCE-7thGen/tree/acff48c2c7e18406fd6000b56945746ca9a6eb69
Legacy4J reference: https://github.com/Wilyicaro/Legacy-Minecraft/tree/80ca31049dd5ea9f7169810f3cadd0aa38114a51

The original LCE HUD, glyph display lists, menu artwork, layout measurements, tooltip font, music timing, PCM sounds and menu navigation behavior carry over from the existing port. Legacy4J supplies the newer workstation screen and menu layouts, sprite artwork, creative listing and crafting groups. Notices retain the upstream authors and licenses. Minecraft's native 1.17.1 title panorama is used, including resource-pack overrides.

PORT-1171-REFERENCE.json records unchanged listing/container-sprite imports and the newer workstation layout sources. Earlier reference manifests document the inherited 1.11.2 implementation and original artwork.

1.17's GLFW input, PoseStack rendering, NativeImage texture uploads, SoundEngine, resource repository, recipe manager, flattened item registries, server menus, packets, save data and world-generation registries replace the removed 1.11 APIs. Source UI layout code is retained behind adapters that call these native systems. Forge mixins replace the old LaunchWrapper transformer. No OptiFine or Minecraft JAR is redistributed.

The C++ interfaces cannot be loaded by Java directly. Renderer, UI and input logic are translated to the available 1.17 APIs. Native 1.17 mechanics remain authoritative: blaze-powder brewing, loom patterns, cartography operations and two-input netherite smithing. Hardcore keeps native death/spectator behavior and the saved console restrictions. Unsupported extra-health, hardcore and ridden-entity HUD states retain Minecraft's appropriate native bars.

In Default/Flat worlds, map enlargement creates a new map on the native fixed grid at the player's current tile, preserving tracking flags and the original map. The grid size doubles with scale and uses Minecraft's original -64 alignment. In the Legacy Overworld, 2.3.2 translates PS4's scale-dependent center calculation and enlarges from the source map's center. Copies retain the source map; names use the server menu, and locked maps retain native restrictions. The held-map presentation is unchanged. See docs/PS4-MAPS-BOUNDS-SPAWN.md for recovered functions, finite coverage, spawn selection, and target-version adapters.

The join add-on chooses the table interface per connection. Its Forge handshake patch clones a single per-connection menu snapshot, removes only legacyconsole:crafting for a peer without Legacy Console, and leaves every other registry and version check active.

2.0.1 resolves the Legacy4J `#candles` and later wool recipe-name differences into native 1.17.1 output families. The user-requested waxed-copper menu exclusion overrides the imported listing without changing its bytes. The separate Maps tab is omitted in favor of native cartography. The music-preserving world-transition redirect targets 1.17.1 updateScreenAndTick. OptiFine iteratable options use H1 setters, shader option sliders use native callbacks, and submenus restore their owning console wrapper.

2.0.2 installs the intro directly on the initial LoadingOverlay constructor/render hooks, before FML client setup. The source Intro720 timeline starts on the loader's first rendered frame, with 4J held until native reload completion. Native resource loading and completion/error handling continue underneath. SoundEngine is initialized against the installed raw music files before sounds.json applies; the initial audio reload preserves the active library and stream while still delivering Forge's normal sound-load event and preloads. Intro music stream preparation uses the existing dedicated music worker; later streams retain Minecraft's executor. The native window begins fullscreen to avoid resizing partially rendered logo frames.

2.0.3 removes the LoadingOverlay mixin because the old 0.8.4 loader skips that target under Java 17 with `PermittedSubclasses requires ASM9`. Minecraft's overlay setter preserves native resource completion while the frame loop queues the intro after the native blit. The original Intro720 images/timeline remain unchanged. Minecraft's Java music-manager tick is suspended while the source LCE playlist owns playback. OptiFine H1's missing TerrainParticle enqueue is repaired after its existing reflected Forge sprite update; geometry, sprite selection, motion and lifetimes remain native. The shader selection marker uses the 1.11.2 wrapper's green selection convention with the current bitmap button font.

2.0.4 restores the native particle sheet order at Forge's ParticleEngine.render key-set iteration. Pickup particles use the entity renderer and clear the lightmap when their batch ends. Sorting the native sheets first, then additional custom types, then the CUSTOM pickup pass prevents that cleanup from blackening subsequent debris/smoke. Identity-key semantics and the relative order of extra custom types are retained. No particle artwork, tint, light values or shader equations are changed.

2.0.5 preserves the pinned Legacy4J crafting JSON and adapts its omissions for native 1.17.1 recipes. Polished blackstone buttons and crimson/warped fences/gates follow the corrected newer Legacy4J listing. The blackstone_brick_* aliases retain their original reference positions under the native polished_blackstone_brick_* names. Cut/smooth sandstone slabs stay beside their sandstone variants. Dye families match output items using the reference color order, including native magenta_dye_from_allium despite the older listing's alium typo. Rockets are handled only by the existing Fireworks side tab, matching LegacyCraftingScreen.groupTabList. Honey bottles postdate LCE and are absent from the crafting listing; they receive a dedicated final Food column following the supplied Legacy4J creative Food placement, rather than the miscellaneous fallback.

2.0.6 defers native window presentation until the first console intro frame completes. GLFW ignores the VISIBLE hint for fullscreen windows, so window creation uses a hidden windowed context at the preferred fullscreen dimensions. Hooks cover Forge's direct handOffWindow call, OptiFine H1's reflected Forge handoff, and H1's native GLFW fallback used for antialiasing. The grouped hooks require a creation path to be matched. The original windowed dimensions remain stored for F11. The constructor's first setMode call is deferred; after the first intro draw has passed through flipFrame and swapped, Window.updateDisplay enters native fullscreen and shows the prepared window once. Later swaps, fullscreen toggles and resource reloads use the normal window lifecycle. The temporary creation hint is restored immediately so other GLFW users keep the default visibility.

2.0.7 calls GLFW.glfwFocusWindow once after the prepared startup window is shown. Entering fullscreen has already made the hidden window visible, and GLFW's show call does not focus an already-visible fullscreen window. The explicit native focus request fixes the actual GLFW_FOCUSED state used by controller polling; it does not replace that check with a synthetic Minecraft active flag. The one-shot startup guard prevents later frames or resource reloads from reclaiming focus after the user switches applications.

2.0.8 uses Minecraft.Client/Input.cpp lines 34-41 and LocalPlayer.cpp lines 276-335 for movement: both axes pass through, the sprint threshold is 0.8, and forward input below that threshold ends sprinting. ConsoleMovement retains the sideways impulse; LocalPlayerMixin also uses the source threshold for native sprint-start checks. The existing config key is retained and its label is now Legacy Sprinting. Minecraft 1.17.1 supplies the remaining movement mechanics.

For ingredient warnings, IUIScene_CraftingMenu.cpp lines 671-741 counts ingredients across inventory stacks, then marks the first missing grid occurrences; lines 1149-1159 display the red boxes. The port uses maximum partial capacity matching to support 1.17.1 ingredient alternatives and exact tags in special crafting. Preview matching assigns available quantities to later occurrences, leaving the same first-deficit squares red. Complete allocation still rejects any unmatched requirement on the server.

PackSelectionScreenMixin.java in the pinned Legacy4J reference (onPress, lines 178-186) independently selects/unselects entries. Assort.updateSavedResourcePacks persists the selected repository order. The port keeps its existing horizontal load/create selector and LCE checkbox/tick art, with a separate ordered pack-selection model. Enabling appends a pack at highest priority; removing one preserves the others; re-enabling appends it above the remaining packs. Native PackRepository order and options.resourcePacks are saved bottom-to-top. Default leaves vanilla and required mod packs enabled.

2.0.9 corrects the missing preprocessing before the 0.8 sprint threshold. Orbis_Minecraft.cpp:963 sets the analog deadzone to 10000 and maximum travel to 32767 (20000 is the separate digital threshold). The provided Orbis 4J_Input.a implementation, INP_Main.o, confirms that CInput::SetJoypadValues processes each axis independently: values inside +/-10000 become zero, positive/negative values subtract/add 10000, and the result is divided by 22767. CInput::Initialise initializes that floating-point divisor. LCE-MOVEMENT-REFERENCE.json records the library SHA-256 and function names.

PadState now retains dedicated LCE movement axes alongside the existing radial menu/look axes. ConsoleMovement uses those dedicated axes when the existing legacy option is enabled. The 0.8 processed-forward threshold remains unchanged; its raw full-circle cutoff is now about 30.6 degrees instead of the old radial filter's roughly 36.9 degrees. Small raw lateral movement up to 10000/32767 is zero even while pushing forward. The option label becomes Legacy Movement and the existing radial setting becomes Look / Menu Deadzone. No arbitrary sprint-angle clamp or blanket lateral blocking is added.

2.0.10 ports creative quick-select actions from IUIScene_CreativeMenu.cpp:789-832, 885-1007 and 1018-1054. One/full-stack items merge only when the complete amount fits, then use an empty slot; a full bar retains the previously used quick-select slot. Clear synchronizes all nine native creative slots (36-44), and outside clicks send native creative-drop packets. Catalog icons are no longer passed through Java's cursor-stack pickup semantics.

The Banners group has explicit create/copy/shield modes, with native shaped banner recipes. Dye Item follows LegacyCraftingScreen's BedItem/ShulkerBoxBlock predicate. Its server-rebuilt, exact-input bed recolor fallback permits colored beds, retaining NBT; only its two declared ingredients match. Ordinary bed dye recipes are hidden while shaped bed creation remains. The loom adapts Legacy4J's classic LoomScreenMixin and LoomMenuMixin coordinates, empty-slot artwork, native 1.17 draw pose and full-size model transforms. New crafting screens seed the observed result revision from the shared menu, so old results do not replay when switching groups.

The loom banner model uses Minecraft's full-bright GUI texturing pass in 1.17.1. It draws the original banner materials and per-pattern dye colors directly through their atlas sprites, avoiding Material.renderType's shared cache. This prevents OptiFine H1 with shaders enabled from applying entity diffuse lighting to flat previews and does not change the world banner materials or shaderpack.

2.0.11 uses IUIScene_TradingMenu::updateDisplay's filtered active-offer list paired with original unfiltered indices. The 1.17 equivalent of isDeprecated is MerchantOffer.isOutOfStock. Exhausted offers are filtered, unfunded offers remain red, and restocked entries resume their native order. Selection keeps the console selector column as offers compact or restock; a changed trade target cancels the old repeat action. Native select/trade packets use the unfiltered index. Eight minimum cells are the user's requested difference from the older source's DISPLAY_TRADES_COUNT=7; more entries use its horizontal scrolling pattern.

The header uses the original MerchantScreen title, because the client-side Merchant wrapper is not the villager Entity. The result name is flattened with Component.getString before formatting strings.resx's IDS_VILLAGER_OFFERS_ITEM wording. skinGraphicsInGame.swf provides IconHolder, IconHolderRed and Warning at character IDs 2, 1 and 158; FJ_SlotList_Slot::SetRedBoxActive places the 16px warning at the 50px slot origin plus one pixel. TRADING-REFERENCE.json records the exports and checksums.
